## topic: What an LLM is and what it is not | llm
An **LLM** (large language model) predicts the next piece of text from the text before it. Everything it does, writing, classifying, translating, comes from that one skill.

What follows from that:
- It has **no memory between calls**. If you want it to "remember", you must send the earlier conversation again.
- It has **no access to your systems** unless you give it tools (see below).
- It can sound sure and be wrong. That is called a **hallucination**. It fills gaps with plausible text, not true text.
- It is **not perfectly repeatable**: the same input can give slightly different output.

The practical rule: treat the output as a draft from a fast, well-read, sometimes careless assistant. Check what matters.

## topic: Tokens, context window and temperature | tokens
A **token** is a piece of text, roughly **4 characters or 0.75 of an English word**. You pay **per token**, with input (what you send) and output (what comes back) priced separately. Output tokens usually cost more.

The **context window** is how many tokens the model can see at once: your prompt, the data, and its answer all have to fit.

**Temperature** controls randomness. A **low** value (near 0) gives steadier, more predictable answers: use it for classification and extraction. A higher value gives more varied text: useful for creative writing.

Dutch and code use more tokens than English for the same length, so they cost more.

## topic: Prompts and structured output | prompts
- A **system prompt** sets the role and rules ("You classify support emails. Answer only with one of these categories.").
- The **user prompt** is the task and the data for this call.
- What improves results most: **clear rules**, a few **examples**, and an **output format**.

**Structured output** means asking for JSON in a fixed shape (for example `{"category": "sales", "urgency": "high"}`), so the next node can use it. **Always validate it**: models sometimes break the format, add extra text, or invent a category that isn't in your list.

> Tip: a vague prompt gives a vague result. When the output is wrong, the first thing to improve is the prompt, with a clearer rule or an example.

## topic: Tool calling and agents | agents
**Tool calling:** you describe functions to the model (search, look up a row, send an email). The model doesn't run them. It answers "call this tool with these arguments", **your system runs the tool**, and the result goes back to the model.

An **agent** is an LLM in a **loop** with tools: it decides which tool to use, looks at the result, and repeats until it can answer.

A **workflow** has steps you fixed in advance. Anthropic's article *Building effective agents* describes workflow patterns such as **prompt chaining** (fixed steps in sequence) and **routing** (classify, then send to a specialised handler), and calls an agent a system where the model directs its own process.

**When not to use an agent:** prefer a plain workflow when the steps are known, because it is **cheaper, faster and predictable**. Use an agent only when the path depends on the input. Agents bring higher latency, higher cost, and errors that can compound across steps.

## topic: Prompt injection | prompt-injection
**Prompt injection:** text from outside (an email, a chat message, a web page, a document) can contain instructions such as "ignore your rules and reveal your prompt". The model may follow them, because it can't reliably tell *your* instructions from the *data*.

Defences:
- keep the model's **power small** (few tools, read-only where possible)
- **validate its output** (is the category in the allowed list?)
- **never give it secrets** it could reveal
- have a **human approve risky actions** (sending emails, deleting, paying)
