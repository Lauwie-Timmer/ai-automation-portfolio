## topic: Calling an API with requests | requests-get
`requests` is the library you installed in p0-4. A **GET** call:

```python
import requests

response = requests.get(
    "https://api.open-meteo.com/v1/forecast",
    params={"latitude": 52.37, "longitude": 4.89, "current": "temperature_2m,wind_speed_10m"},
    timeout=10,
)
```

- `params={...}` builds the query string for you (`?latitude=52.37&...`) and encodes it correctly.
- `timeout=10` stops waiting after 10 seconds. **Without a timeout the call can hang forever**; the requests docs say nearly all code should set one.
- `response` is a **Response object** holding everything the server sent back.

Useful parts: `response.status_code` (e.g. `200`), `response.url` (the final URL, handy to check your params), `response.headers`, and `response.json()`.
cmd: `requests.get(url, params={...}, timeout=10)` | sends a GET request and returns a Response object
know: Send a GET with params and a timeout
Q: Why always pass `timeout=`?
A: Without one the script can wait forever if the server never answers.
Q: What does `params={...}` do?
A: It builds and encodes the query string (`?key=value&...`) for me.

## topic: Reading the response and checking status | response
`response.json()` turns the JSON body into Python dicts and lists. But **a successful `.json()` does not mean the call succeeded**: an error response (like a 500) can also contain JSON. Check the status first:

```python
response.raise_for_status()      # raises HTTPError on 4xx and 5xx; does nothing on 2xx
data = response.json()
```

`raise_for_status()` makes a failed call fail **loudly**, instead of letting your script carry on with an error message as if it were data. If the body isn't valid JSON, `.json()` raises a `JSONDecodeError`.

Network problems (no internet, wrong host name) raise `requests.exceptions.ConnectionError`; a timeout raises `requests.exceptions.Timeout`. All of them inherit from `requests.exceptions.RequestException`.
cmd: `response.raise_for_status()` | raises an error on 4xx/5xx status codes
cmd: `response.json()` | turns the JSON body into Python dicts and lists
know: Check the status before using the body
know: Name what raise_for_status does and why
Q: Does a successful `response.json()` prove the request worked?
A: No. A 500 error can also return JSON. Check the status or call `raise_for_status()`.
Q: What does `raise_for_status()` do?
A: Raises an HTTPError for 4xx/5xx so a failed call can't pass silently.

## topic: Reading nested JSON | nested-json
Open-Meteo answers with nested JSON, roughly:

```json
{
  "current": { "time": "2026-10-05T14:00", "temperature_2m": 14.2, "wind_speed_10m": 11.3 }
}
```

You reach a value by indexing step by step:

```python
temp = data["current"]["temperature_2m"]
print(f"{data['current']['time']}: {temp} C, wind {data['current']['wind_speed_10m']} km/h")
```

**Always print the whole JSON first** so you can see its real shape and copy the key names exactly (a typo like `["orers"]` is a very common bug):

```python
import json
print(json.dumps(data, indent=2))
```

A `KeyError: 'x'` means the key isn't there: check the spelling and the nesting level against the printed JSON.
know: Print the full JSON to see its shape before indexing
know: Read a value from nested dicts and lists
Q: You get `KeyError: 'temperature'`. What do you do first?
A: Print the whole JSON with `json.dumps(data, indent=2)` and check the exact key names and nesting.
Q: Write the line that reads the temperature from `{"current": {"temperature_2m": 14.2}}` held in `data`.
A: `data["current"]["temperature_2m"]`
