## topic: Why the CLI | why-cli
n8n's built-in Git feature (**source control and environments**) is only in paid plans. The free route is the **CLI** (command-line tool) that ships **inside** the n8n image. You run it inside the container with `docker exec`.

Goal of this step: every workflow saved as a **readable file in Git**, so you can see what changed and roll back. A client workflow should be restorable in **under 10 minutes**.

> Tip: the docs say to prefix commands with `docker exec -u node -it <container>` when running interactively. Your container is named `n8n` (p0-3).

## topic: Exporting: docker exec and docker cp | export
**Export all workflows**, one readable file each, inside the container:

```
docker exec n8n n8n export:workflow --all --separate --pretty --output=/tmp/wf
```

- `docker exec n8n` runs a command inside the container named `n8n`
- `n8n export:workflow` is the CLI command
- `--all` every workflow; `--separate` **one file per workflow**; `--pretty` readable formatting, so Git shows clear differences; `--output=/tmp/wf` the folder **inside the container**

The files land inside the container, so **copy them out** to your repo folder (run from `C:\dev\automation-portfolio`):

```
docker cp n8n:/tmp/wf/. .\workflows
```

`docker cp source destination` copies between the container and your PC. The `.` after `/tmp/wf/` means "the contents". Run `docker exec n8n n8n export:workflow --help` any time to see the current options (they change between versions).

> Warning: **never export credentials into Git.** `n8n export:credentials` writes secrets; with `--decrypted` they are readable. Keep credentials out of the repo completely.

## topic: Seeing changes and committing: git diff | git-diff
Commit after the export, with a one-line message that says what and why: `add retry to the weather HTTP node`.

To **see exactly what changed**: change a workflow in n8n, export again, copy again, then run:

```
git diff
```

`git diff` shows the lines that changed since the last commit (red removed, green added). Because of `--pretty` and `--separate`, a small change in n8n is a small, readable change in one file.

**Habit:** export and commit **before every meaningful change**. To mark a version you hand to a client, tag it:

```
git tag v1.0
```

A **tag** is a permanent label on a commit. List tags with `git tag`.
cmd: `git diff` | shows what changed since the last commit
cmd: `git tag v1.0` | puts a version label on the current commit

## topic: Restoring: import:workflow | import
To restore a workflow from its file, copy it into the container and import it:

```
docker cp .\workflows\my-workflow.json n8n:/tmp/restore.json
docker exec n8n n8n import:workflow --input=/tmp/restore.json
```

Importing a workflow whose **id already exists updates it**. For a whole folder use `--separate --input=/tmp/folder/`. After importing, **check that it is published again**: by default an import leaves imported workflows unpublished (the `--activeState` flag defaults to `false`, and `fromJson` only works in multi-main setups). Publish it in the editor, or run `docker exec n8n n8n publish:workflow --id=<ID>` and restart n8n, because a CLI change only takes effect after a restart.

Rolling back a client's workflow: find the last good commit (`git log --oneline`), check out or copy that file, import it, check it is published, test it.

**Environments:** keep development and production apart. Name credentials clearly (`Google (dev)`, `Google (prod)`) and use different keys, so a test can never touch real data.
cmd: `docker exec n8n n8n import:workflow --input=/tmp/restore.json` | imports a workflow file from inside the container

## topic: Doing it | doing-it
1. Run the export, copy the files into `workflows\` in your repo, open one file, and commit with a clear message.
2. Change a workflow in n8n, export again, and use `git diff` to see exactly what changed.
3. Delete a workflow in n8n, restore it from the file with the import command, and check it works and is active.
4. Add `git tag v0.1`. Write the three commands you'll use (export, copy, import) in `workflows\README.md`.

Done when your repo holds one readable file per workflow, you restored a deleted workflow from Git, and you can explain why credentials never go in the repo.
