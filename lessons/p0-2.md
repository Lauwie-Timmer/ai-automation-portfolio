## topic: Git vs GitHub | git-vs-github
These two names sound alike and do different jobs.

- **Git** is a program on your computer. It records versions of your files. Each saved version is called a **commit**, like a save point in a game: you can look back at it or return to it later.
- **GitHub** is a website. It stores a copy of that history online, so you have a backup and can share work with other people.

Git works without GitHub. GitHub is just one place to keep a copy of what Git records.

The copy on your own computer is **local**. The copy on GitHub is the **remote**. They are two copies of the same project, linked together. Your work happens locally; the remote is the backup and the meeting point.

```
your PC (local)   <---- linked ---->   GitHub (remote)
Git records the history                stores a copy of it online
```

## topic: Repository, private and README | repository
A **repository** (**repo**) is one project folder plus its whole history. This roadmap uses one repo, `automation-portfolio`, for all your scripts and exported n8n workflows. It will become your portfolio.

**Private** means only you, and people you invite, can see the repo. The opposite is public, where anyone can. Choose private now: this is practice work, and later it may hold things you don't want everyone to read. You can make it public later if you want to show it to a client.

A **README** is a text file at the top of a repo that says what the project is. GitHub shows it on the repo's front page. Ticking "Add a README" when you create the repo gives you a first file, so the repo is not empty and can be downloaded.

## topic: Cloning | cloning
**Cloning** means downloading a repo from GitHub to your computer. You get all the files and the whole history, and the copy stays **linked** to the remote, so the two can be kept in sync later.

Cloning is different from downloading a ZIP. A ZIP is just files. A clone is a repo: it knows where it came from and carries its history.

In this step you clone with **GitHub Desktop**, a program with buttons for Git: File, Clone repository, pick `automation-portfolio`, and set the local path to `C:\dev\automation-portfolio`. The path matters: later steps assume your repo is at exactly that place.

You clone once per computer. After that you work in the folder.

## topic: .gitignore | gitignore
`.gitignore` is a text file in the repo that lists files Git must **never track or upload**. Typical entries:
- secrets, such as a `.env` file (you'll make one in p0-5)
- the folder for your Python packages (`.venv`, from p0-4)
- junk generated by programs

Why it matters: anything Git tracks gets uploaded to GitHub, and anything uploaded can leak. A key in a tracked file is a key on the internet. `.gitignore` is how you keep secrets and clutter out.

When you create the repo you choose a **.gitignore template**. Pick **Python**: it already lists the common Python files, including `.venv`. You can add more lines yourself later, one pattern per line.

> Warning: `.gitignore` only works for files Git is not tracking yet. Add a secret to it *before* the file is ever committed.

## topic: git status | git-status
`git status` shows what Git thinks of the folder you are in: which files changed, which are new and untracked, and whether you are in sync with the remote. You run it **inside the repo folder**. Outside a repo it says "not a git repository".

Right after a fresh clone it should say something like:

```
On branch main
Your branch is up to date with 'origin/main'.

nothing to commit, working tree clean
```

Read it as: you are on the main line of history, you match GitHub, and no file has changed. `origin` is Git's default name for your remote. In p1-6 you will learn the rest of the Git commands properly; for now you only need `git status`, because from p0-4 on you will use it to check that secrets and the `.venv` folder stay out of Git.

## topic: Doing the setup | setup
Do this yourself. Never share your GitHub password with anyone, including Claude.

1. Go to github.com and sign up or log in.
2. Click **New repository**. Name: `automation-portfolio`. Choose **Private**. Tick **Add a README**. Choose the **Python** .gitignore template. Create it.
3. In GitHub Desktop: File, Clone repository, pick `automation-portfolio`, set the local path to `C:\dev\automation-portfolio`, clone.
4. In VS Code: File, Open Folder, choose `C:\dev\automation-portfolio`. Open the terminal with Ctrl and the backtick key (left of the 1 on a US keyboard) and run `git status`.

How to check you did it right, without anyone else: in PowerShell run `cd C:\dev\automation-portfolio`, then `ls`. You should see `README.md` (and a hidden `.git` and `.gitignore`). Claude can also check that the folder exists.

> Tip: the name must be exactly `automation-portfolio`, in lowercase with a hyphen. A different name gives a different folder and later steps will not find it.
