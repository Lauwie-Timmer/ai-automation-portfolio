## topic: The four tools and what each is for | four-tools
You will use four programs all the way through this roadmap. Each one does one job.

| Tool | What it is | What you use it for here |
|---|---|---|
| **Python** | A programming language | Your own scripts, API calls, and later AI agents |
| **Node.js** | A runtime that runs JavaScript outside a browser | Your Expo app. You don't need it for n8n |
| **Git** | A program that records versions of your files | Saving your work with history, and backing it up |
| **Docker** | A program that runs other programs in isolated boxes called *containers* | Running n8n on your own PC without installing it into Windows |

A **runtime** is the program that reads your code and runs it. Python code needs Python installed. JavaScript code outside a browser needs Node.

> Note: n8n is built on Node, but it ships its own copy of Node inside the Docker container. So the Node on your PC is for your app, not for n8n.

The one-sentence version of each, which you must be able to say without looking:
- Python runs my scripts.
- Node runs JavaScript, and I have it for my app.
- Git keeps the history of my files.
- Docker runs n8n in a container so it doesn't mess with my PC.
know: Say in one sentence what Python, Node, Git and Docker are each for
know: Explain why Node is installed even though n8n runs in Docker
Q: In one sentence each: what are Python, Node, Git and Docker for in this roadmap?
A: Python: my own scripts, API calls and agents. Node: runs JavaScript, I have it for my Expo app. Git: records versions of my files. Docker: runs n8n in an isolated container.
Q: n8n is built on Node. Why don't you have to manage Node for n8n?
A: n8n runs inside a Docker container that already includes its own Node, so the Node on my PC isn't used for it.

## topic: Checking versions | check-versions
Every one of these tools can tell you its version. This is the quickest way to prove it is installed, and the first thing to run when something doesn't work.

```
python --version
node --version
git --version
docker --version
```

Each prints one line such as `Python 3.10.7`. If the command is not found, PowerShell shows a red error saying the name is not recognised. That means the tool is missing or not on your PATH.

> Tip: `docker --version` only checks that the Docker program exists. It works even when Docker Desktop is closed. Commands that actually run containers (like `docker ps`) need Docker Desktop open with the engine running. You'll see that in p0-3.

cmd: `python --version` | prints the installed Python version
cmd: `node --version` | prints the installed Node version
cmd: `git --version` | prints the installed Git version
cmd: `docker --version` | prints the Docker version (works even if Docker Desktop is closed)
Q: How do you check whether Git is installed?
A: Run `git --version` in PowerShell. A version line means it's installed; a red "not recognised" error means it's missing.
Q: `docker --version` works but `docker ps` fails. What is the most likely reason?
A: Docker Desktop is closed or its engine isn't running. `--version` only checks the program exists; `docker ps` needs the engine.
