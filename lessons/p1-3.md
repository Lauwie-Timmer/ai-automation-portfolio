## topic: POST with json= | post-json
A **POST** sends data in the **body**. With `requests` you pass a Python dict to `json=`:

```python
import requests

payload = {"name": "test", "message": "hello from python"}
response = requests.post(
    "https://webhook.site/your-unique-id",
    json=payload,
    headers={"X-Source": "python"},
    timeout=10,
)
print(response.status_code)
```

What `json=` does for you:
1. converts the dict to JSON text
2. sets the header `Content-Type: application/json`
3. puts it in the request body

`data=` is different: it sends a **form** (`key=value&key2=value2`), not JSON. And `json=` is ignored if you also pass `data=` or `files=`. Passing `data=json.dumps(payload)` sends JSON text but does **not** set the `Content-Type` header, which is why `json=` is better.

A custom header goes in `headers={...}`. `X-Source: python` is just a name we made up, to find it later.
cmd: `requests.post(url, json={...}, headers={...}, timeout=10)` | sends a POST with a JSON body
know: Send a POST with json= and a custom header
know: Explain json= versus data=
Q: What three things does `json=` do?
A: It converts the dict to JSON, sets the `Content-Type: application/json` header, and puts it in the body.
Q: What changes if you use `data=` instead of `json=`?
A: It sends form-encoded data (`key=value&...`), not JSON, and doesn't set the JSON content type.

## topic: Seeing what you sent: webhook.site | webhook-site
**webhook.site** gives you a free unique URL and shows every request that arrives at it: the **method**, the **headers** and the **body**. It is a good way to see exactly what your script sent.

1. Open https://webhook.site and copy your unique URL.
2. Put it in your script and run it. Reload webhook.site and click the request.
3. Find: the method (`POST`), your header `X-Source: python`, the `Content-Type` header, and the body.

> Warning: the URL is **public**. Anyone who has it can read what you send. Send fake data only: no real names, emails or keys.

Practice: change the body to include a list of two items, for example `"items": ["a", "b"]`, run again and find the list in the body on webhook.site.
know: Find the method, headers and body of your request on webhook.site
know: Say why only fake data goes to webhook.site
Q: Why must you only send fake data to webhook.site?
A: The URL is public, so anyone with it can read the requests.
Q: Where on webhook.site do you check that your custom header arrived?
A: In the request's headers list: `X-Source: python`.
