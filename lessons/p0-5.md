## topic: API keys and why they are secret | api-keys
An **API key** is a password that lets your code use a service, such as Google's Gemini AI. The service uses it to know who is calling, to bill you, and to apply limits. **Anyone who has your key can use your account**, and you pay or get blocked for what they do.

Rules:
- **Never commit a key to Git.** Bots scan GitHub for leaked keys within minutes.
- **Never paste a key into a chat**, including with Claude, and never into a screenshot.
- If a key leaks: **delete it in the provider's console and create a new one**. Removing it from your files afterwards is not enough, because it stays in the Git history and someone may already have copied it.

A **free tier** means limited requests per minute and per day at no charge. It is fine for learning.

## topic: .env and .gitignore | env-gitignore
A **.env file** holds secrets as `NAME=value` lines, one per line, in the project folder:

```
GEMINI_API_KEY=your-key-goes-here
```

No quotes, no spaces around the `=`. Your code reads the file at run time, so the secret never appears in your source code. `.gitignore` lists `.env`, so Git never uploads it.

An **.env.example** is a copy with the names but **no values**:

```
GEMINI_API_KEY=
```

You **do** commit `.env.example`. It tells other people (and future you) which variables the project needs without exposing any secret.

The order matters: add `.env` to `.gitignore` **before** the file ever gets committed. After that it is too late for that file.

Check it works: run `git status`. `.env` must **not** appear in the list. If it does, add a line `.env` to `.gitignore`.

Q: Why is there a `.env.example` file, and why is it committed while `.env` is not?
A: It lists the variable names without values so others know what to set, and it holds no secret. `.env` holds the real key, so it stays out of Git.
Q: How do you check that Git ignores your `.env`?
A: Run `git status`. `.env` must not appear. If it does, add `.env` to `.gitignore`.
Q: What is wrong with `GEMINI_API_KEY = "abc"` in a .env file?
A: The format is `NAME=value` with no spaces and no quotes.

## topic: Reading .env in Python | read-env
The package **python-dotenv** reads a `.env` file into your program. Install it with your venv active:

```
python -m pip install python-dotenv
```

Then in Python:

```python
from dotenv import load_dotenv
import os

load_dotenv()
key = os.getenv("GEMINI_API_KEY")
```

`load_dotenv()` reads `.env`; `os.getenv("NAME")` returns the value, or `None` if it isn't set.

**Never `print(key)`.** Printing it puts the secret in your terminal and any screenshots. To test that it loaded, print only whether it exists:

```python
print(bool(key))
```

This prints `True` or `False`. The one-line test from the terminal:

```
python -c "from dotenv import load_dotenv; import os; load_dotenv(); print(bool(os.getenv('GEMINI_API_KEY')))"
```

`True` means the key was found. `False` means the file, the name, or the working folder is wrong: run it from the folder that holds `.env`, and check the name is spelled exactly the same.

Last, update the package list: `pip freeze > requirements.txt`.
cmd: `python -m pip install python-dotenv` | installs the package that reads .env
cmd: `pip freeze > requirements.txt` | saves the package list again

## topic: The free key and client data | free-tier
Google's terms say that for users in the EEA, Switzerland and the UK, the paid-service data rules apply even to free usage, so your prompts aren't used to improve their products. The same terms say you may use **only paid services** when you make an API client available to users in those regions.

In plain words: **the free key is for your own practice, with fake data.** Anything a client or their customers use must run on a paid account, ideally the client's own. Never send a client's real data through your learning key.
