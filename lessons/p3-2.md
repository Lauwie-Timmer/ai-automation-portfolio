## topic: The AI nodes in n8n | ai-nodes
n8n has ready-made AI nodes. They work in **pairs**: a **root node** that does the job, plus a **sub-node** that provides the model.

- A **chat model** node (for example **Google Gemini Chat Model**) holds your model and credential.
- It plugs into a root node: **Text Classifier**, **Information Extractor** or a **Basic LLM Chain**.

Node names change a little between n8n versions. If one is missing, search the nodes panel for the idea.

**Credential and key:** create a credential for Google Gemini with the API key from p0-5. Paste the key only there. This free key is for **learning with fake messages only**: Google's terms say that you may use only paid services when you make an API client available to users in the EEA, Switzerland or the UK, so client work later runs on the client's own paid account.

## topic: Text Classifier | text-classifier
The **Text Classifier** sorts text into **categories you define**. You give each category a **name and a description**, and the node's output has one branch per category.

Key settings:
- **Input Prompt**: the text to classify, as an expression, for example `{{ $json.body.message }}`
- **Categories**: name + description for each (`sales`, `support`, `spam`, `other`)
- **Allow Multiple Classes To Be True**: off by default (one category per message)
- **When No Clear Match**: discard the item, or send it to an **Other** output
- **Enable Auto-Fixing**: asks the model to fix badly formatted output

**The categories and their descriptions are the prompt.** Make them precise: "support: the customer has a problem with something they already bought or use" beats "support". Keep an `other` route for the unexpected so nothing disappears.

Q: Why are the category descriptions so important?
A: They are the prompt the model works from. Precise descriptions give correct routing.
Q: What happens to a message that fits no category if you discard unmatched items?
A: It disappears silently. Better to route it to an Other output.

## topic: Information Extractor | extractor
The **Information Extractor** pulls **named fields** out of text into JSON. Define the schema with **From Attribute Descriptions**: each attribute has a **name**, a **type**, a **description** and whether it is **required**. (Other options: generate from a JSON example, or provide a JSON Schema.)

Example attributes: `name` (string, the sender's name) and `urgency` (string, one of low, medium or high). Write the allowed values in the description, then **validate** the result later (p3-5): the model may still return something else.

If a field isn't in the text, a required attribute can make the model guess. Mark fields optional if the text may not contain them.
know: Define attributes for the Information Extractor
Q: What are the parts of an attribute in the Information Extractor?
A: Name, type, description and whether it is required.
Q: Why does marking everything required cause trouble?
A: If the text lacks a field the model may invent a value to satisfy the requirement.

## topic: Testing with hard inputs | testing
Test with **hard** inputs, not only easy ones: a rude message, a message in Dutch, two topics at once, an empty message, a message that tries to give the AI orders. **Writing the test list is the real skill.**

Build `08 message classifier`:
1. **Webhook** (POST, path `classify`), then **Text Classifier** with categories `sales`, `support`, `spam`, `other`, each with a one-line description.
2. Then **Information Extractor** for `name` and `urgency` (low, medium, high).
3. Route each category to its own **Edit Fields** that adds `route`, such as `sales-team`.
4. Write 12 test messages in `tests/classify.json` (4 of them hard) with the expected category, send them with a Python loop, and record a table: message, expected, got.
5. Improve the descriptions until at least **11 of 12** are right. Note what you changed and why.

Low temperature is used so results are steadier between runs.

Q: Name four kinds of hard test messages.
A: A rude message, one in Dutch, two topics at once, and an empty message (also one that gives orders to the AI).
Q: Why do you change one description at a time and re-run?
A: To see which change helped or hurt, instead of guessing.
