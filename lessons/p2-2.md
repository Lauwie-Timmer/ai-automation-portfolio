## topic: Why validate first | why-validate
Real data is messy: a form arrives with no email, a name full of spaces, a number as text. A reliable workflow **checks its input before doing anything expensive or visible** (writing to a sheet, sending an email, calling a paid API). Bad data caught at the door costs nothing; bad data in your sheet costs time and trust.

The plan for this step: a webhook that receives a signup, checks it, and answers the sender with the right **status code**:
- good data: `200` and `{"ok": true}`
- bad data: `400` and `{"ok": false, "error": "invalid input"}`

The status code is how the caller knows what happened. Your Python script can read the code and react (retry, show an error, stop).

Q: Why does validation go before the expensive or visible steps?
A: Bad data should be stopped at the door, before it writes to a sheet, sends an email or costs money.
Q: Which status code means bad input, and who is at fault?
A: 400, the caller sent something wrong.

## topic: The IF node | if-node
The **IF node** splits items into two paths by a condition: a **true** output and a **false** output.

A condition has three parts: a **value** (the data you test), a **data type** (String, Number, Date & Time, Boolean, Array or Object) and an **operator** that fits the type (for strings: *contains*, *is empty*, *is not empty*, and more; for numbers: *is greater than*).

Several conditions combine with **AND** (all must be true) or **OR** (any one is enough). For the signup check you want AND:
1. `{{ $json.body.email }}` **contains** `@`
2. `{{ $json.body.name }}` **is not empty**

Edge cases a checker will ask about: an email with spaces, a missing `body`, a `null` value, a name that is only spaces. Think about what your conditions do with each.

know: Name the true and false outputs and the parts of a condition
Q: What are the parts of an IF condition?
A: A value, a data type, and an operator that matches the type.
Q: What is the difference between AND and OR in the IF node?
A: AND needs every condition true; OR needs at least one.

## topic: Expressions that run JavaScript | js-expressions
Between `{{` and `}}` you can use ordinary JavaScript methods on the data:

```
{{ $json.body.email.toLowerCase() }}      "Ann@X.COM" becomes "ann@x.com"
{{ $json.body.name.trim() }}              removes spaces at the start and end
{{ $json.body.email.includes("@") }}      true or false
{{ $json.body.first + " " + $json.body.last }}    join text with +
```

Keep to this handful: `toLowerCase`, `trim`, `includes` and joining with `+`.

Remember from p1-5: the JSON your script sent is under **`body`** (`$json.body`). Headers and query parameters are next to it (`$json.headers`, `$json.query`). If an expression returns nothing, open the node's output and look.

If a field is missing, `$json.body.email.toLowerCase()` fails (you can't call a method on nothing). That is one more reason to validate before you transform.

A: If the field is missing the call fails, because there is nothing to call it on.

## topic: Respond to Webhook | respond-to-webhook
By default the Webhook node answers immediately with a short message. To send **your own answer**, do two things:

1. In the **Webhook node**, set **Respond** to **Using 'Respond to Webhook' node**. (Other options: Immediately, When Last Node Finishes.)
2. Add a **Respond to Webhook** node. Choose **Respond With** (for example **JSON**) and enter the body, e.g. `{"ok": true}`. Under options set the **Response Code** (`200` or `400`). Headers can be added there too.

By default the node answers with the **first** incoming item only. To return several items, use All Incoming Items or combine them first.

If you forget step 1, your Respond node is ignored and the caller gets the default reply.
know: Set the Webhook Respond option and add Respond to Webhook with a code
Q: Which setting on the Webhook node makes it wait for a Respond to Webhook node?
A: Respond: Using 'Respond to Webhook' node.
Q: Where do you set the HTTP status code of the answer?
A: In the Respond to Webhook node's options, as Response Code.
