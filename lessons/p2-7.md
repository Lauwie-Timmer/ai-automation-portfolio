## topic: A workflow is a JSON file | workflow-json
A workflow downloads as a **JSON file**. You can **import** it into any n8n: drag the file onto the canvas, or use the **...** menu. This is how you deliver work to clients and share with friends, and it is your backup.

Open one in VS Code. You'll find:
- `name`: the workflow's name
- `nodes`: a list, each with a `name`, a `type` (such as `n8n-nodes-base.httpRequest`), `parameters` (its settings) and `credentials` (a **reference** by name and id)
- `connections`: which node feeds which

n8n's own Git feature (source control and environments) is only in paid plans, not in the Community edition you run. In p2-8 you'll version workflows with the CLI. For now you export by hand.
know: Find the name, nodes, parameters and credential reference in the file
Q: Where in the JSON file do you find which node connects to which?
A: In `connections`.
Q: How do you import a workflow file into n8n?
A: Drag the file onto the canvas, or use the ... menu and import it.

## topic: What an export contains, and what it doesn't | export-contents
An export holds the **node settings** but **not your credential secrets**: only the credential *names*. So a file is generally safe to share.

But check for anything sensitive anyway:
- webhook paths (they are part of the URL)
- keys typed into an expression or a Code node by mistake
- real email addresses, names or other personal data in example data or pinned data
- a hard-coded `@` address of a real person

In VS Code use Search (Ctrl+F) in the file for `@` and `key`.

You can ask Claude to review an exported workflow, but **strip any real personal data first**.

Q: Does an exported workflow contain your Google password or token?
A: No, only the credential name. But hard-coded keys in expressions or Code nodes would be in the file.
Q: What do you search for in an export before committing it?
A: `@` and `key`, plus webhook paths and any real personal data.
