## topic: The AI Agent node and its parts | agent-parts
The **AI Agent** node is an agent that uses **tools** (n8n calls it a Tools Agent). It needs:
- a **chat model** (for example Google Gemini Chat Model), which does the thinking
- **at least one tool**: the tools you attach are the **only things the agent can do**
- optionally **memory**: **Simple Memory** keeps the recent chat messages so the agent remembers what was said earlier in the conversation

The **Chat Trigger** gives you a chat window to talk to the agent. Memory matters because the LLM itself has no memory between calls (p3-1): without it every message starts from nothing.

know: Explain what memory is for
Q: What can an n8n agent do?
A: Only what its attached tools allow, plus thinking and answering.
Q: Why does the agent need memory in a chat?
A: The LLM has no memory between calls, so memory feeds the recent messages back in.

## topic: Tools and their descriptions | tool-descriptions
The model chooses a tool from each tool's **name and description**. Bad descriptions give wrong tool choices: **treat a tool description as a short prompt.**

Two tools for this step:
- **Calculator**: for maths, which LLMs get wrong when they guess
- **HTTP Request Tool**: calls the Open-Meteo weather API. Write one clear sentence, including what it needs, for example: "Gets the current temperature in Amsterdam. Use latitude 52.37 and longitude 4.89."

Compare a vague description ("weather stuff") with a clear one and watch the agent's behaviour change. That is the point of the "break a description on purpose" exercise.
know: Write clear tool descriptions
Q: How does the agent decide which tool to call?
A: From each tool's name and description, so the descriptions work like a prompt.
Q: Write a good one-sentence description for a weather tool.
A: For example: "Gets the current temperature in Amsterdam from Open-Meteo, using latitude 52.37 and longitude 4.89."

## topic: Reading the Logs | logs
After a run, open the **Logs** panel. You see each **thought, tool call and result**, in order. This is how you debug agents: which tool did it pick, with which arguments, and what did it do with the answer?

Ask three questions in the chat and note the tools used and their order each time:
1. "What is 18% of 240?" (expects: Calculator)
2. "What is the temperature in Amsterdam now?" (expects: weather tool)
3. "What is 15% of the temperature in Amsterdam?" (expects: weather tool first, then Calculator)

The third one shows the loop: the result of one tool becomes the input of the next.
know: Read the Logs to see tool calls in order
Q: For "What is 15% of the temperature in Amsterdam?", which tools are used and in what order?
A: The weather tool first, then the Calculator, because the second needs the result of the first.

## topic: Least power and approvals | least-power
Give agents the **least power** they need. Every tool is something the model can do on your behalf, including by mistake or after a prompt injection (p3-1).

A tool that can **delete rows** or **send emails to customers** needs a **human approval step** before you use it for a client. A read-only tool (weather, lookup) is far safer.

Questions to ask for each tool you attach: what is the worst thing it could do if the model is wrong or tricked? Can I make it read-only? Does a person need to approve first?
know: Explain why tools get the least power and when approval is needed
Q: What is risky about giving an agent a "send email" tool?
A: A wrong choice or a prompt injection could email real customers, which can't be undone. It needs human approval.
