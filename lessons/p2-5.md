## topic: The Code node | code-node
The **Code node** runs your own JavaScript (or Python). Use a standard node when one exists; use Code when the logic would otherwise take five nodes.

It has two modes: **Run Once for All Items** (the default: your code runs once and sees every item) and **Run Once for Each Item**.

In the default mode:
- read the incoming items with `$input.all()`; each item's data is `item.json`
- you must **return a list of objects shaped like `{ json: {...} }`**

```javascript
// create items
return [
  { json: { id: 1, customer: "Ava", amount: 30 } },
  { json: { id: 2, customer: "Ben", amount: 120 } },
];

// read all items and add up an amount
const total = $input.all().reduce((sum, i) => sum + i.json.amount, 0);
return [ { json: { total } } ];
```

`reduce` walks through the list keeping a running total: start at `0`, add each `amount`. Return the wrong shape (a plain object, or items without `json`) and the node errors.

Use `console.log(...)` to debug: it prints in your **browser's** developer console. Code can't read files or make HTTP calls; use dedicated nodes for that. Python is also available, but JavaScript is the default and has the most examples.

Q: What shape must a Code node return in "Run once for all items" mode?
A: A list of objects, each with a `json` key: `[{ json: {...} }]`.
Q: How do you read all incoming items in a Code node?
A: `$input.all()`; each item's data is `item.json`.
Q: Where does `console.log` output appear?
A: In the browser's developer console.

## topic: The Switch node | switch
The **Switch** node is an IF with **more than two outputs**. In **Rules** mode you build one rule per output (a value, a type, an operator), and outputs are numbered in rule order: the first rule is Output 0, then 1, and so on. (Expression mode returns the output number from code.)

Two settings to know:
- **Fallback Output**: what to do with items that match no rule. **None** (the default) **discards** them; **Extra Output** sends them to a separate output; **Output 0** puts them with the first rule's items.
- **Send Data to All Matching Outputs**: off by default, so an item goes only to the **first** matching rule.

For your sizes: rule 1 `amount` less than `50` → small; rule 2 between `50` and `200` → medium; rule 3 above `200` → large. Mind the **edge cases**: an `amount` of exactly 50, and a missing `amount`. With *no fallback*, a missing amount **silently disappears**.

Q: What happens to an item that matches no Switch rule by default?
A: It is discarded (Fallback Output: None).
Q: If a rule says "greater than 50" and another "less than 50", where does an amount of exactly 50 go?
A: Nowhere: it matches neither, so without a fallback it disappears. Use "greater than or equal" for one rule.

## topic: The Merge node | merge
The **Merge** node joins branches back together. Its modes:

| Mode | What it does |
|---|---|
| **Append** | keeps all items from all inputs, one after the other (supports several inputs) |
| **Combine** | merges two inputs: by **Matching Fields**, by **Position**, or **All Possible Combinations** |
| **SQL Query** | joins with SQL (you can ignore this for now) |
| **Choose Branch** | passes through one input's data |

After a Switch splits 6 items over three branches, **Append** puts them back into one list of 6. Without Merge the three branches stay separate, and the next node would only see one branch.
know: Choose between Append and Combine
Q: After a Switch splits items over three branches, which Merge mode brings them back into one list?
A: Append.
Q: What does Combine by Matching Fields do?
A: Joins items from two inputs where the chosen field values match.

## topic: Building order labels | build-labels
New workflow `06 order labels`:

1. **Manual Trigger**, then a **Code** node returning 6 sample orders (`id`, `customer`, `amount`).
2. **Switch** on `amount`: under 50 is small, 50 to 200 is medium, above 200 is large.
3. On each branch an **Edit Fields** node adds `label` with the right word.
4. Bring all three branches back with **Merge** (Append; set the number of inputs to 3).
5. Check that you get **6 items** out, each with its label.
6. Add a second **Code** node that adds up all amounts into one item.

Check the edge cases with the Checker: an amount of exactly 50, and a missing amount.

Done when you get 6 labelled items and one total, and you can explain what shape a Code node must return and why Merge is needed.
