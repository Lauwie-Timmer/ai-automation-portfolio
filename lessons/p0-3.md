## topic: What Docker and n8n are | what-docker-is
**n8n** is a tool for building automations by connecting blocks ("nodes") on a canvas: when X happens, do Y, then Z. It runs as a small web server, and you use it in your browser.

**Docker** runs programs in isolated boxes called **containers**. Instead of installing n8n and everything it needs into Windows, you tell Docker to run n8n in a container. It stays separate from the rest of your PC, you can stop it or delete it cleanly, and anyone with Docker gets the same setup.

Two parts of Docker, which people confuse:
- **Docker Desktop** is the app with the **engine** inside. The engine is what actually runs containers.
- The **`docker` command** you type in PowerShell is only a remote control that talks to the engine.

If Docker Desktop is closed, the remote control has nothing to talk to. You get an error like "failed to connect to the docker API" (or "cannot connect to the Docker daemon"). Fix: open Docker Desktop and wait until it says **Engine running** at the bottom left.

> Warning: `docker --version` works even with Docker Desktop closed, because it only checks that the program exists. `docker ps` and `docker run` need the engine running.

## topic: Image vs container | image-vs-container
- An **image** is a frozen recipe: a program plus everything it needs to run. It doesn't run by itself. You download it once. `n8nio/n8n` is the name of the n8n image on **Docker Hub**, the public library of images.
- A **container** is a running copy made from an image, like a program started from an installer.

You can make many containers from one image, and delete a container without losing the image. Next time you start one from the same image it is a fresh copy.

Because a container is disposable, anything it writes **inside itself** is lost when the container is removed. That is why n8n needs a *volume*, next topic.

```
image  n8nio/n8n   ---docker run--->   container n8n (running)
                    ---docker rm--->   container gone, image still there
```
cmd: `docker run hello-world` | downloads a tiny test image and runs it once, proving Docker works
cmd: `docker images` | lists the images downloaded on your PC

## topic: Ports: -p 5678:5678 | ports
A container has its own private network. To reach a program inside it from your browser, you connect a **door** on your PC to a door inside the container. This is **port mapping**:

```
-p HOST:CONTAINER
-p 5678:5678
```

- The **left** number is the port on your PC (the host).
- The **right** number is the port inside the container. n8n always listens on 5678 inside.

`localhost` always means **your own computer**, so `http://localhost:5678` in your browser goes to door 5678 on your PC, which Docker forwards to door 5678 in the container.

If you write `-p 5679:5678`, the left number changes: you now browse to `http://localhost:5679`, and n8n inside still listens on 5678. Only the left number can change freely. Changing the right number breaks it, because n8n isn't listening there.

**"port is already allocated"** means something else on your PC already uses the left port. Run `docker ps` to see which container, or choose a different left number.

## topic: Volumes: -v n8n_data:/home/node/.n8n | volumes
A **volume** is storage that lives **outside** the container. n8n keeps your account, workflows and saved logins (n8n calls them *credentials*) in the folder `/home/node/.n8n` inside the container. Without a volume, that folder would be thrown away with the container, and you'd start over each time.

```
-v n8n_data:/home/node/.n8n
    ^name    ^folder inside the container
```

Read it as: "store that folder in a volume called `n8n_data`". The container can be stopped, removed and re-created, and a new container with the same `-v` finds all your data again.

- Delete the **container**: you lose nothing. The data is in the volume.
- Delete the **volume**: you lose your n8n account and all workflows.

```
docker volume create n8n_data     make the volume
docker volume ls                  list volumes
docker volume rm n8n_test         delete a volume (permanent!)
```

> Warning: never run `docker volume rm n8n_data` unless you want to start over. Remove only the test volume you made for practice.
cmd: `docker volume create n8n_data` | creates the volume that will hold n8n's data
cmd: `docker volume ls` | lists your volumes
cmd: `docker volume rm name` | permanently deletes a volume and everything in it

Q: What does the volume protect?
A: My n8n account, workflows and credentials, which live in /home/node/.n8n and would otherwise vanish with the container.
Q: What happens to your workflows if you delete the container? If you delete the volume?
A: Container deleted: nothing lost, the volume still has them. Volume deleted: all my n8n data is gone.
Q: Read `-v n8n_data:/home/node/.n8n` in plain words.
A: Keep the folder /home/node/.n8n (inside the container) in a volume named n8n_data, outside the container.
Q: Which command makes the volume, and which one lists your volumes?
A: `docker volume create n8n_data` makes it; `docker volume ls` lists them.

## topic: The other flags and the full command | flags
```
docker run -it --rm --name n8n -p 5678:5678 -v n8n_data:/home/node/.n8n -e GENERIC_TIMEZONE=Europe/Amsterdam -e TZ=Europe/Amsterdam -e N8N_ENFORCE_SETTINGS_FILE_PERMISSIONS=true -e N8N_RUNNERS_ENABLED=true n8nio/n8n
```

| Part | Meaning |
|---|---|
| `docker run` | make a container from an image and start it |
| `-it` | show its output in my terminal, interactive. Stop it with Ctrl+C |
| `-d` | run in the **background** instead of `-it` |
| `--rm` | delete the container when it stops (the volume stays) |
| `--name n8n` | give the container a name so I can stop it by name |
| `-p 5678:5678` | port mapping |
| `-v n8n_data:/home/node/.n8n` | volume |
| `-e NAME=value` | set an environment variable inside the container |
| `GENERIC_TIMEZONE`, `TZ` | the timezone. It matters for scheduled workflows |
| `N8N_ENFORCE_SETTINGS_FILE_PERMISSIONS=true` | n8n locks its settings file so other users on the PC can't read it |
| `N8N_RUNNERS_ENABLED=true` | code you run inside n8n later runs in a separate, safer process. n8n's docs say it is deprecated from n8n 2.0 (the current version) and no longer needed, so it is harmless to keep or to leave out |
| `n8nio/n8n` | the image to use. Always last |

The **daily-use** version swaps `-it --rm` for `-d --restart unless-stopped`: it runs in the background and restarts with Docker.

> Note: n8n changes its recommended command from time to time. In October 2026 its plain-Docker page was already marked "outdated" in favour of **Docker Compose**, which describes the same container in one file (you meet it in p6-4). `docker run` is still the clearest way to learn what each flag means, so we start here. After it works, open the n8n Docker pages and compare them with what you typed. Checking the official docs is a habit you need all the time.

```
docker ps            what is running
docker ps -a         including stopped containers
docker logs n8n      show the container's output
docker stop n8n      stop it
docker start n8n     start a stopped one
docker rm n8n        delete the container
```

**"container name already in use"**: an old container called `n8n` still exists. Run `docker rm n8n`, then try again.

## topic: Doing it: steps and what to look for | doing-it
Do these yourself and try for 15 minutes before asking for help.

1. Open **Docker Desktop**, wait for **Engine running**. The first start can take a minute and may ask to enable WSL 2. Accept.
2. `docker run hello-world`. A short message proves Docker works.
3. `docker volume create n8n_data`
4. Start n8n in the foreground with the full command from the previous topic. The first run downloads the image (a few hundred MB). Wait for a line saying the editor is accessible at `http://localhost:5678`, then open it and create the owner account. It stays on your computer.
5. Open a second PowerShell window, run `docker ps`, find `n8n`. Go back to the first window and press **Ctrl+C**. Run `docker ps` again: n8n is gone, because of `--rm`. Your account is still in the volume.
6. Run the daily version in the background:

```
docker run -d --restart unless-stopped --name n8n -p 5678:5678 -v n8n_data:/home/node/.n8n -e GENERIC_TIMEZONE=Europe/Amsterdam -e TZ=Europe/Amsterdam -e N8N_ENFORCE_SETTINGS_FILE_PERMISSIONS=true -e N8N_RUNNERS_ENABLED=true n8nio/n8n
```

Open `localhost:5678`: your account still works, proving the volume kept it.

If Docker Desktop says virtualization is disabled, it has to be switched on in the BIOS. That depends on your PC, so ask Claude to walk you through it.

Q: After Ctrl+C, `docker ps` no longer lists n8n. Why, and is your account lost?
