## topic: The Schedule Trigger | schedule
The **Schedule Trigger** starts a workflow at set times. Its **Trigger Rules** are: Seconds, Minutes, Hours, Days, Weeks, Months, or **Custom (Cron)** for advanced patterns. For "every day at 08:00" choose Days and set the hour.

Three things people get wrong:
- It only fires when the workflow is **published** (older versions: Active). Clicking Execute workflow just runs it once.
- It uses a **timezone**. The workflow's own timezone setting takes precedence; otherwise the n8n instance's. You set `GENERIC_TIMEZONE` in your Docker command in p0-3, so the instance runs in your zone.
- It only runs while **n8n is running**. On your laptop, a workflow won't fire while the laptop is off or Docker is closed. Clients' workflows run on a server for that reason.

Test with Execute workflow. Don't wait for 08:00.

Q: Your 08:00 workflow didn't run while your laptop was shut. Why?
A: The Schedule Trigger only fires while n8n (Docker) is running, and only when the workflow is published.
Q: Which timezone does a schedule use?
A: The workflow's own timezone setting if set, otherwise the instance timezone (GENERIC_TIMEZONE).

## topic: Parallel arrays and Split Out | split-out
Some APIs return **parallel arrays**: several lists where position matches. Open-Meteo's daily forecast is an example:

```json
{ "daily": {
    "time":              ["2026-10-06", "2026-10-07", "2026-10-08"],
    "temperature_2m_max":[14.2, 16.1, 12.0],
    "precipitation_sum": [0.0, 3.4, 1.2] } }
```

It is **one item** holding three lists. But n8n works on items, so you want one item **per day**. The **Split Out** node does that: in **Fields To Split Out** you name the list fields (comma-separated): `daily.time, daily.temperature_2m_max, daily.precipitation_sum`. For 7 days you get 7 items. Its **Include** option controls whether other fields are kept (No Other Fields, All Other Fields, Selected Other Fields).

Check the result in the Output: **7 items**, each with a time, a temperature and a precipitation value.

Q: What problem does Split Out solve?
A: One item holding lists becomes one item per list element, so each day can be processed on its own.

A: 7 items, each with one value from each list.

## topic: Filter and Aggregate | filter-aggregate
The **Filter** node keeps only items that match a condition and **discards** the others. Conditions work like the IF node's: value, data type, operator; combine them with AND or OR (not mixed). Example: keep days where precipitation is **greater than 1** (mm).

The **Aggregate** node merges many items back into **one**. Modes: **Individual Fields** (collect chosen fields into lists) and **All Item Data** (put all the data in one list in one field). You need it before a single summary email, because of the "once per item" rule.

Think it through: 7 items go straight into Gmail → **7 emails**. 7 items → Filter (rainy days, say 3) → Aggregate (1 item) → Gmail → **1 email**.

Q: What happens if 7 items go straight into the Gmail node without Aggregate?
A: Gmail runs once per item, so 7 separate emails go out.
Q: What does Filter do with items that fail the condition?
A: It discards them: only matching items continue.
