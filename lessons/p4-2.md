## topic: What makes a script sellable | sellable
Clients pay for scripts that **save them time every week**. So the script has to be reliable, documented and easy to run. A script without a README is only half a deliverable.

A good small script has:
1. a **clear purpose** (one sentence),
2. **settings in one place** (command-line arguments, or a `.env` file as in p0-5),
3. **error handling** (API down, empty data, bad argument) with a clear message,
4. **logging**, not only `print`,
5. a **tested core function** (the calculation),
6. a **README** a stranger can follow.

Your mathematics background is an advantage here: statistics, trends and clean calculations are what turn raw data into a report someone wants.

**The spec for Project B:** fetch the last N days (argument `--days`, default 30) of EUR to USD and GBP, compute the **minimum, maximum, average and percentage change** for each, write `report.csv` and print a readable summary.

## topic: Getting data from the API | api
Use the free **Frankfurter** exchange-rate API (no key). Its docs (checked October 2026) show the current form:

```
https://api.frankfurter.dev/v2/rates?from=2026-09-01&to=2026-09-05&base=EUR&quotes=USD,GBP
```

It returns a list with one entry per currency per day:

```json
[{"date":"2026-09-01","base":"EUR","quote":"GBP","rate":0.85603},
 {"date":"2026-09-01","base":"EUR","quote":"USD","rate":1.1599}]
```

The older `/v1/2026-09-01..2026-09-05?base=EUR&symbols=USD,GBP` form still answered on 2026-10-05 but returns a different shape. Always check the docs for the current URL. If the API ever stops working, Open-Meteo weather data does the same job.

**It only has working days**, so a 30-day request returns about 20 days. That's normal: never hard-code 30 values.

In Python:

```python
import requests
from datetime import date, timedelta

end = date.today()
start = end - timedelta(days=30)
params = {"from": start.isoformat(), "to": end.isoformat(),
          "base": "EUR", "quotes": "USD,GBP"}
r = requests.get("https://api.frankfurter.dev/v2/rates", params=params, timeout=10)
r.raise_for_status()      # raises an error for 4xx/5xx
rows = r.json()
```

- `date.today() - timedelta(days=30)` gives the start date; `.isoformat()` turns it into the `2026-09-05` text an API wants.
- `timeout=10` stops the script hanging forever; `raise_for_status()` turns an error reply into an exception you can catch.
know: Build the date range and request URL for the last N days
know: Say why a 30-day request returns fewer than 30 values
Q: How do you get the date 30 days ago as text for an API?
A: `(date.today() - timedelta(days=30)).isoformat()`
Q: Why does a 30-day request return about 20 values?
A: The API only has working days (no weekends), so you must not hard-code a count.
Q: Why add `timeout=10` and `raise_for_status()`?
A: So the script doesn't hang forever, and so an HTTP error becomes an exception you can handle.

## topic: argparse: settings from the command line | argparse
`argparse` lets you run `python report.py --days 30` and read the value in your code.

```python
import argparse

parser = argparse.ArgumentParser(description="EUR exchange-rate report")
parser.add_argument("--days", type=int, default=30)
args = parser.parse_args()
print(args.days)
```

## topic: logging and error handling | logging
`print` is for the report. **`logging`** is for what the script *did*, with timestamps and levels (INFO, WARNING, ERROR), so a problem can be traced later.

```python
import logging

logging.basicConfig(level=logging.INFO,
                    format="%(asctime)s %(levelname)s %(message)s")
logging.info("fetched %d rows", 22)
logging.error("failed: %s", "API down")
```

**Handle the failures you can predict:**

```python
try:
    rows = fetch_rates(days)
except requests.RequestException as e:      # API down, timeout, bad status
    logging.error("could not fetch rates: %s", e)
    return 1
if not rows:
    logging.error("API returned no data")
    return 1
```

Return a non-zero exit code on failure (`sys.exit(1)`) so whoever runs it, or a scheduler, can tell it failed. Never print secrets in a log.

## topic: The calculation, CSV and pytest | tests
Keep the calculation in its **own function** that takes numbers and returns numbers, so it can be tested without the internet:

```python
def summarise(values):
    first, last = values[0], values[-1]
    return {"min": min(values), "max": max(values),
            "avg": sum(values) / len(values),
            "change_pct": (last - first) / first * 100}
```

**CSV:** `import csv`, then:

```python
with open("report.csv", "w", newline="") as f:
    w = csv.DictWriter(f, fieldnames=["quote", "min", "max", "avg", "change_pct"])
    w.writeheader()
    w.writerow({"quote": "USD", "min": 1.12, "max": 1.14, "avg": 1.13, "change_pct": -1.4})
```

Open the file with `newline=""` or Windows adds blank lines.

**pytest** runs your tests. Install it with `python -m pip install pytest`. In a file named `test_report.py`:

```python
from report import summarise

def test_average():
    assert summarise([1, 2, 3])["avg"] == 2

def test_change():
    assert summarise([100, 110])["change_pct"] == 10
```

Then run `pytest`. A test is a function whose name starts with `test_` and that uses `assert`. Test the **calculation**, not the API call. Use small hand-made numbers whose answer you can work out yourself.
cmd: `python -m pip install pytest` | installs pytest into the active environment
cmd: `pytest` | runs every test_ function in test_*.py files
