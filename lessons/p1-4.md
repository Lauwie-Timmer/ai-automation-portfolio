## topic: Workflows, nodes and triggers | workflow-basics
n8n draws an automation as a **workflow**: a chain of boxes called **nodes**, connected by lines, on a canvas. Data flows from left to right.

- The first node is always a **trigger**: it decides what starts the workflow. A **Manual Trigger** starts it when you click **Execute workflow**. Later you'll use a Webhook trigger and a Schedule trigger.
- Every other node does one job: call an API, change fields, send an email, make a decision.
- Open n8n at `http://localhost:5678` (your Docker container from p0-3 must be running).

A node's setup lives in its panel. Double-click a node to open it. The left shows **Input** (what arrives), the middle holds the node's **parameters**, and the right shows **Output** (what it produced).

Name every workflow clearly, e.g. `01 weather to webhook`. In three months you'll have fifty.

## topic: Items | items
n8n passes data between nodes as **items**. An **item** is one JSON object. A node receives a list of items and does its job **once per item**, then passes the results on.

```
Input: 2 items                        Output: 2 items
[ {"name": "Anna"},                   [ {"name": "Anna", "greeting": "Hi Anna"},
  {"name": "Ben"} ]                     {"name": "Ben",  "greeting": "Hi Ben"} ]
```

Internally each item wraps your data in a key called `json`, which is why expressions start with `$json`.

In the Input and Output panels you can switch between three views: **Schema** (a tidy tree), **Table**, and **JSON** (the raw text). When something looks wrong, check the JSON view: it shows the truth.

The output of one node is the input of the next. Run a single node with **Execute step**; n8n keeps its output, so you can build the next node on **real data** instead of guessing.

## topic: The HTTP Request node | http-request
The **HTTP Request** node does what Python's `requests` did in p1-2 and p1-3.

| Python | HTTP Request node |
|---|---|
| `requests.get(url, ...)` | Method: **GET**, URL |
| `params={...}` | **Send Query Parameters** |
| `headers={...}` | **Send Headers** |
| `json={...}` | **Send Body**, content type **JSON** |
| `requests.post(...)` | Method: **POST** |

Setup for your weather call: Method `GET`, URL `https://api.open-meteo.com/v1/forecast`, turn on **Send Query Parameters** and add `latitude`, `longitude` and `current`. Click **Execute step** and open the Output.

By default the node returns **only the body**. To also get the status code and headers, turn on **Include Response Headers and Status** in its options.

Sending an API key has its own settings in this node. Until Phase 2 you only call free APIs that need no key.

## topic: Expressions and Edit Fields | expressions
An **expression** is a bit of code inside `{{ }}` that n8n evaluates to a value, so a field can use data from earlier nodes.

```
{{ $json.current.temperature_2m }}          a field of the current item
{{ $('HTTP Request').item.json.current.time }}   a field from a specific earlier node
{{ $now }}                                   the current date and time
```

- `$json` means "the data of the item that arrived at this node".
- To use an expression, set the field to **Expression** mode (the Fixed / Expression toggle on the field), then type it or **drag a field from the Input panel** into the box. Dragging builds the correct expression for you.
- The names must match the JSON exactly: print it in the Output JSON view and copy the names.

The **Edit Fields** node (also called Set) creates or changes fields. In **Manual Mapping** mode you add fields with a name and a value (fixed or an expression). Turn on **Keep Only Set Fields** to throw away every other field.

For your workflow: after the HTTP node add Edit Fields that keeps only `time`, `temperature` and `wind`, each pointing at the HTTP node's output with an expression.

## topic: Sending data on, and saving your work | sending-on
Add a second **HTTP Request** node after Edit Fields: Method `POST`, URL your webhook.site address, **Send Body** with content type **JSON**, and the three fields (use the field values from the previous node). Run the workflow and check on webhook.site that the three fields arrived.

Then:
- Name the workflow `01 weather to webhook` and **Save** it (Ctrl+S).
- Run it again from a **Manual Trigger** with **Execute workflow**.
