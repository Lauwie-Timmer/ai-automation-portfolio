## topic: Three ways models fail | failures
Models fail in three ways. Plan for each:

1. **The API errors**: the service is down, a key expired, a rate limit (429) hits.
2. **The output format breaks**: the JSON is incomplete, or the category isn't in your list.
3. **The answer is confidently wrong**: well-formed, plausible and false.

Defences, in order: **retry** for the first, **validate** for the second, and for the third a **review route** and **measuring** (p3-eval), because you can't fully remove it.

Q: Name the three ways an AI step fails.
A: The API errors, the output format breaks, or the answer is confidently wrong.
Q: Which of the three can't validation catch?
A: A confidently wrong but well-formed answer.

## topic: Validate and route to review | validate
**Validate output**: is the category in the allowed list? Is the JSON complete? Is `urgency` one of low, medium or high? Anything unsure goes to a **human review path** instead of being guessed. Keep an `other` or `needs review` route.

In `08 message classifier` add an **IF** (or Switch) after the classifier: if the category is missing or the extracted urgency isn't low, medium or high, send it to a `needs review` branch.

Think through special inputs: an **empty message**, a very long one, and a **prompt-injection message** ("ignore your instructions and..."). What does your workflow do with each?

## topic: Logging and retries and limits | logging-retries
**Log every call** (time, input, output, category, route) to a sheet, so you can answer "why did it do that?" later. Don't log sensitive personal data unless you must.

**Retry On Fail** on the model call helps with API errors (p2-6: only for actions that are safe to repeat; a classification is).

**Cost limit:** set a daily or monthly budget limit in the provider's console, so a loop or an attack can't run up a huge bill.

**Secrets and personal data:** never put secrets or personal customer data in a prompt unless the client has agreed and the provider's terms allow it.
